# TwinKeys 2.4 の設計案：Yamaha QL の卓のフェーダーを引き継ぐ（承認待ち）

図：`docs/design/mac-ql-dark`（中身は架空のサンプル）

## ねらい

メインの Mac が止まったとき、卓（Yamaha QL）でメインの Mac の音が入っているチャンネルを下げ、バックアップの Mac のチャンネルを、メインが直前まで出ていた高さまで上げる。音の出口の切り替えを、人の手を待たずに（または確認1回で）行う。

## 調べたこと

| 区分 | 内容 | 出典 |

## 動き

1. 卓とつなぐのは**バックアップの Mac だけ**（メインが止まったとき、生きている側が卓を動かすため）。
2. ふだんから、メイン用チャンネルのフェーダーの高さを 0.2 秒ごとに読み続ける（「いまの高さ」に表示）。
3. 切り替えのとき（バックアップの Mac がメインになったとき）：
   - バックアップ用チャンネルを、メイン用チャンネルの**直前の高さ**まで上げる。
   - 同時に、メイン用チャンネルを −∞ まで下げる（チャンネルの ON/OFF はさわらない）。
   - フェード時間は「すぐ／0.5 秒／1 秒／2 秒」から選ぶ（初期値 0.5 秒）。
4. 「卓を元に戻す」で逆向きに戻せる。
5. 切り替えの起こし方：
   - **確認してから（初期値）**：「この Mac をメインにする」の確認に「卓のフェーダーも切り替える」を付ける（iPhone からの切り替えでも同じ）。
   - **自動**：メインが 3 秒応答しないとき、すぐ切り替える。回線が一瞬切れただけでも動くおそれがあるため、選ぶときに注意を出す。

## 安全のための決めごと

- 卓とつながっていない・つながりが不安定なときは、切り替えボタンに「卓は動かせません」と出し、Mac の切り替えだけ行う。
- 卓から読んだ高さが古い（2 秒以上更新がない）ときは、自動の切り替えはしない。
- 送るのはフェーダーの値だけ。EQ・ダイナミクス・ルーティングなどには触れない。
- 実機で確かめるまでは「試験的な機能」とし、初期状態はオフ。

## 作り方

- QL の真似をする試験用の仕組み（同じ書式に答える小さな TCP サーバー）を作り、テストはそれで行う。
- 実機での確認項目を確認表に足す（つなぐ・高さを読む・切り替え・元に戻す・回線を抜く）。
