# サイトの「触って試す」（iPhone・Apple Watch のデモ画面）の設計案（承認待ち）

図：`docs/design/site-demo-light`（パソコン）・`site-demo-failover-light`（メインを止めたとき）・`site-demo-mobile-dark`（スマホ）。中身はすべて架空のサンプルです。

## ねらい

サイトを見た人が、TwinKeys Remote と Apple Watch の操作を、その場で触って分かるようにする。特に「1回押すと2台の Mac に同時に届く」「メインが止まったら切り替えられる」を体験できるようにする。

## 置き場所

トップページの「iPhone・iPad から2台の Live を操作」の段のすぐ下に「触って試す」の段を足す（日本語・英語の両方）。
JavaScript が動かないときは、今の画面の画像をそのまま出す。

## 画面（図のとおり）

- **iPhone**：パソコンでは横向き、スマホの幅では縦向き（アプリと同じく、幅で決める）。
  - 上の帯：つながりの状態・再生・停止・テンポ・全ノートオフ・本番ロック。
  - 動く画面は **GO** と **セッション**（クリップのます目）の2つ。ミキサー・キュー・設定は薄く表示し、押せない（「アプリで使えます」と出す）。
- **Apple Watch**：GO・シーンを選ぶ・全ノートオフの3画面。下の点で切り替え。クラウンの代わりに「▲ 前」「次 ▼」ボタン。
  iPhone と Watch は同じ状態を見ているので、片方で GO を押すともう片方も進む。
- **2台の Mac**：「Main Stage Mac」「Backup Stage Mac」のカード（つながりの図と同じく、メインを上、バックアップを下に縦に並べる）。押した操作を同時に受け取ったことを「↓ GO を受け取りました 2 ms」で示す（音は鳴らない）。
- **メインの Mac を止めてみる**：押すとメインのカードが赤く「応答なし」になり、iPhone に赤い帯「メインの Mac が応答しません」が出る。「バックアップに切り替える」→「長押しで切り替え」を 1 秒押すと、iPhone がバックアップにつなぎ直し、バックアップのカードに「メイン」の印が付く（アプリと同じ流れ）。
- **はじめに戻す**：最初の状態に戻す。
- **つながり**：Apple Watch ― iPhone ― の先で線がコの字に分かれ、縦に並べた Main Stage Mac（上）と Backup Stage Mac（下）につながる図。上の枝は「直接」、下の枝は「メイン経由（LAN）」。つながっている線は緑、切れた線は赤の点線と ✕。メインを止めると、iPhone からバックアップへの青い点線（「切り替えると、iPhone はバックアップに直接つなぎ直します」）が出る。切り替えたあとは、iPhone の線がバックアップに直接つながり、「メイン」の印がバックアップに移る。スマホの幅では Watch と iPhone を縦に並べ、その下でコの字に分かれて2台の Mac を横に並べる。

## 技術の選び方

| 候補 | 動作の軽さ | 配布サイズ（増える分） | 作りやすさ | 対応ブラウザ | 将来性 | AI での書きやすさ |
|---|---|---|---|---|---|---|
| **A. Astro ＋ TypeScript だけ（部品の仕組みなし）** | ◎ | 自前のコードだけ（約 10 KB の見込み） | ○（状態が少ないので十分） | ◎ 今のサイトと同じ | ◎ 追加の依存なし | ◎ |
| B. Astro ＋ Preact | ◎ | ＋約 5 KB（推測） | ◎ | ◎ | ○ | ○ |
| C. Astro ＋ React | ○ | ＋約 60 KB（推測） | ◎ | ◎ | ◎ | ◎ |

**おすすめ：A**。デモの状態は「シーンの一覧・再生中・次・本番ロック・メインが生きているか・切り替え済みか」程度で少なく、画面の部品の仕組み（React など）を入れなくても素直に書けます。サイトに新しい依存を足さずに済み、読み込みも一番軽いです。目安の「動く部分だけ React」より、この規模なら A が合っていると判断しました（配布サイズの数字は推測）。

- 使うもの：Astro 7.4.7（サイトで今使っている版。最新は 7.4.11 だが、勝手に上げない）。出典：https://www.npmjs.com/package/astro
- 比べた版（npm で確認、2026-11-12）：@astrojs/preact 6.1.5 ＋ preact 11.2.0、@astrojs/react 7.1.8 ＋ react 19.3.1。

## 部品の分け方とフォルダ

```
site/src/components/RemoteDemo.astro   画面の骨組み（iPhone・Watch・Mac のカード・操作ボタン）と見た目
site/src/lib/remote-demo.ts            状態と操作（画面に触らない純粋な関数。テストしやすくする）
site/src/lib/i18n.ts                   文言（日本語・英語）を足す
```

## 状態とデータ

```ts
type DemoState = {
  scenes: { name: string; color: string }[]; // 架空の 8 シーン（アプリのデモと同じ）
  playing: number | null;   // 再生中のシーン
  next: number;             // 「次」（Live で選んでいるシーン）
  startedAt: number;        // 残り時間の計算用（再生を始めた時刻）
  locked: boolean;          // 本番ロック
  pane: 'go' | 'session';
  watchPage: 'go' | 'scenes' | 'panic';
  main: 'ok' | 'dead';      // メインの Mac（見本の中だけ）
  switched: boolean;        // バックアップに切り替えた
  lastEvent: { label: string; at: number } | null; // Mac のカードに出す「受け取りました」
  watchLinked: boolean;     // Apple Watch と iPhone（見本では常に true）
};
```

- 操作は `go()`, `select(i)`, `launchClip(t, s)`, `allNotesOff()`, `toggleLock()`, `stopMain()`, `switchToBackup()`, `reset()`。それぞれ新しい状態を返すだけの関数にする。
- GO の 0.5 秒以内の2回目は受け付けない（アプリと同じ）。

## 使いやすさ

- ボタンはすべて本物のボタン（キーボードで押せる）。長押しは、キーボードではスペースを 1 秒押し続ける。
- 状態が変わったら、読み上げ用の隠れた欄（aria-live）で「シーン 4 M1 本編を再生しました」などと知らせる。
- 動きを減らす設定（prefers-reduced-motion）のときは、光る演出を出さない。
- スマホの幅（390 px）で横にはみ出さない。押す場所は 44 px 以上。

## 確かめ方

- Playwright（ブラウザを自動で動かす道具。この環境に入っている）で、パソコンとスマホの幅の画像を撮って確かめる。
- GO・前へ・次へ・Watch の GO・メインを止める→切り替え・はじめに戻す、を自動で押して、表示が変わることを確かめる。
