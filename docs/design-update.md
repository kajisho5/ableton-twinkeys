## 1. 目的と方針

新しいバージョンが出たら、自動で見つけてダウンロードしておく。ライブ用のアプリなので、次の3つを必ず守る。

1. **本番中に勝手に入れ替えない・再起動しない。** 入れ替えは「TwinKeys を終了したとき」か、相手とつながっていないときに人が「いま再起動」を押したときだけ
2. **確認の画面（ダイアログ）を勝手に出さない。** 知らせは画面の上の帯だけにし、演奏の邪魔をしない
3. **本物だけを入れる。** ダウンロードしたアプリは、今のアプリと同じ開発者（チーム ID）と同じアプリ ID の Developer ID 署名があるか確かめる。違えば入れない

## 2. 仕組みの選び方

| 観点 | A. Sparkle（Mac で定番のアップデート部品） | B. 自前（zippeek と同じ方式、おすすめ） |
|---|---|---|
| 動作の軽さ | 普通（フレームワークを1つ同梱） | 軽い（OS の機能だけ） |
| 配布サイズ | 数 MB 増える **[推測]** | ほぼ増えない |
| 作りやすさ | 更新情報のファイル（appcast）と専用の署名鍵の管理が増える。同梱するフレームワークの署名を runway で扱えるか未確認 | zippeek で実績のある書き方をそのまま使える。runway の変更はいらない |
| 「本番中は入れ替えない」の作り込み | 細かい制御は設定の範囲内 | 自由に作れる |
| 本物の確かめ方 | Sparkle 独自の署名（EdDSA）とコード署名 | コード署名（Developer ID、チーム ID、アプリ ID） |
| 将来性 | 長く使われている定番 | 自前なので保守は自分たち |
| AI での書きやすさ | 普通 | 書きやすい（短い） |

**おすすめは B（自前）です。** 理由は2つあります。
- zippeek で同じ仕組みが動いている（CI で入れ替えまで確かめている）
- 「本番中は入れ替えない」というライブ向けの決まりを、細かく作り込める

## 3. 動き

1. **確認のタイミング**：起動して1分後と、その後6時間ごと。GitHub の「リリース一覧」の窓口を見る（`/repos/kajisho5/ableton-twinkeys/releases`）
   - 「最新リリース」の窓口（`/releases/latest`）は、お試し版（プレリリース）を返さない。今の 0.x はすべてお試し版なので、一覧からいちばん新しいバージョンを選ぶ **[事実]** https://docs.github.com/en/rest/releases/releases#get-the-latest-release
   - 下書きは除く。お試し版は含める（今は全部がお試し版のため）。1.0 からは正式版だけにするかを、そのとき決める
2. **ダウンロード**：新しい版があれば、`.dmg` を `~/Library/Caches/TwinKeys/Updates/` へ裏でダウンロードし、中のアプリを取り出して署名を確かめる
   - 確かめる条件：`anchor apple generic` かつアプリ ID が `io.github.kajisho5.twinkeys` かつ証明書のチーム ID が今のアプリと同じ
   - 条件に合わなければ捨てて、ログに残す
3. **知らせる**：画面の上に帯を出す。「TwinKeys 0.6.0 の準備ができました。TwinKeys を終了したときに入れ替わります。本番中には入れ替えません。」
   - **相手とつながっていないとき**だけ「いま再起動」ボタンを出す（押すとオールノートオフを送ってから入れ替え、起動し直す）
   - つながっているときはボタンを出さない
4. **入れ替え**：TwinKeys を終了するとき（⌘Q など）に、準備済みのアプリと入れ替える。次に開くと新しいバージョンになる
   - 入れ替えられない場所にあるとき（書き込みできないフォルダなど）は、リリースのページを開くよう案内する
5. **設定**：「新しいバージョンを自動で確認してダウンロードする」（最初はオン）、今のバージョン、「今すぐ確認」ボタン
6. **メニュー**：「TwinKeys」メニューに「アップデートを確認…」

## 5. テスト

- 単体テスト：バージョンの比べ方（0.10.0 > 0.9.1、`-beta` 付き）、リリース一覧から選ぶ処理（下書きは除く、`.dmg` が無いものは除く）
- CI（Mac）：わざと「新しい版」に見せた一覧を手元で配り、ダウンロード → 署名の確認 → 終了時の入れ替えまでを自動で確かめる（zippeek と同じやり方）
  - 署名なしの CI ビルドでは「署名が合わないので入れない」側の動きを確かめる
  - 本物の入れ替えは、リリース時の確認の工程（公証済みのアプリ）で確かめる
- 手順書：本番中（接続中）に帯が出ても入れ替わらないこと、終了で入れ替わること

## 6. メニューバー常駐（追加の提案）

ウインドウを閉じても TwinKeys は動き続ける。そのことと接続の状態を、メニューバーのアイコンで常に見えるようにする。

- **アイコン**：Apple の SF Symbols のピアノ鍵盤の図柄（`pianokeys`）を、白黒の型（テンプレート画像）で使う。つながっているときは塗りつぶし、それ以外は線だけ。再接続中は点滅させず、形だけで区別する **[推測：図柄の名前は実装時に確認。無ければアプリアイコンを単色化して使う]**
- **メニューの中身**（`docs/design/menubar-*.svg`）：
  - 状態（例「○○ に接続済み」と遅延）
  - オールノートオフ（⌃⌘P、赤字）
  - 接続／接続解除（⌘K）、キー入力（⌃⌘K）
  - TwinKeys を開く、設定…（⌘,）
  - ログイン時に起動（チェック）
  - TwinKeys を終了（⌘Q）
- **ログイン時に起動**：macOS 13 から使える `SMAppService.mainApp` で登録する。最初はオフ。バックアップの Mac で便利 **[事実]** https://developer.apple.com/documentation/servicemanagement/smappservice
- **Dock**：最初は今までどおり Dock にも出す。設定に「メニューバーだけに表示する」を用意する（Dock のアイコンを消す）
- **作り方**：SwiftUI の `MenuBarExtra`（macOS 13 から）を使う **[事実]** https://developer.apple.com/documentation/swiftui/menubarextra
- **注意**：Live を全画面にしているとメニューバーは隠れる。本番中の状態表示は、これまでどおりウインドウが主役
- **README の Roadmap** にあった「メニューバー常駐（v2 候補）」を前倒しして入れる
